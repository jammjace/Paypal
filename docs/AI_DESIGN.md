# Milestone 4: Ask Pal and classification

AI interprets; code calculates; the user decides. Ask Pal is now a working read-only form with prompt buttons, pending/error states and clearly labeled results. It operates on the server-resolved workspace only.

## Query path

`askPalAction` validates a question (1-500 characters), resolves the session owner and reads the workspace. `askPal` uses either a configured structured interpreter or a deliberately limited local grammar. `querySchema` accepts only BALANCE, COMPARE_SPENDING, MERCHANT, CATEGORY, TOP_MERCHANT, INCOME, BUCKET, ACTION or UNSUPPORTED, plus an entity and this/last-month period.

The model receives the question and bucket/merchant/category names, not financial-provider payloads, account IDs or balances. Names and questions are treated as untrusted data. Entity names must resolve to the current workspace. Unsupported/ambiguous requests produce a clarification, never an invented record. All authoritative numbers and final explanation text are generated by `answerQuery` using the finance engine. No second LLM call rewrites the calculated answer.

Queries cover Safe to Spend, equivalent calendar-day comparisons, merchant total/count/average, category totals, top merchant, income partitions, current spending-budget allowance and current savings progress/contribution plan. Previous-month spending queries use that full calendar month. Current results use the normalized snapshot clock, not the host clock. Historical balances and historical bucket snapshots are unsupported. Data is limited to stored provider coverage; provisional categories participate and unclassified purchases may change category totals after review. Gross spend excludes transfers/refunds, following existing analytics policy.

ACTION recognizes money-change requests but cannot execute them or create approvals. It directs the user to explicit savings forms. ProposedAction tradeoffs, approval and expiry belong to milestone 5. Ask Pal does not mutate financial state or persist chat transcripts. Each question is standalone; follow-up pronouns/context are not supported.

## Free local-only inference and fallback

**No payment, credit card, paid API, hosted inference account or cloud subscription is required.** The paid-provider path has been removed. Default: `PAL_AI_MODE=local`, a limited deterministic grammar labeled **Local fallback**. It is not an LLM and works without downloads or credentials.

The optional actual model is **Qwen3 4B (`qwen3:4b`) via local Ollama**. The server adapter fixes both the model tag and loopback endpoint (`http://127.0.0.1:11434/api/chat`); it accepts no external base URL, cloud tag or API key and rejects HTTP redirects. The local computer supplies inference resources.

## This workspace's local runtime

The VS Code Ollama extension is installed, but it is a client for an Ollama server; it does not contain the inference runtime or weights. A portable official Ollama runtime is now installed in `.local/ollama/runtime`, with weights in `.local/ollama/models`. Both are ignored by Git. No global PATH or VS Code settings were changed.

- Runtime: Ollama v0.40.0, official Windows AMD64 release archive.
- Archive SHA-256: `3623e256762ca89bd6fa99b0cc4106401919ce9df926411673e632e3ea287bb5`, verified against official release metadata before extraction.
- Model: local `qwen3:4b` (Apache 2.0, approximately 2.5 GB weights).
- This machine: approximately 16 GB RAM, Intel integrated graphics; inference uses CPU.

Start the local service after a reboot:

```sh
npm run ai:start
npm run dev
```

The launcher starts a hidden process on `127.0.0.1:11434`, sets `OLLAMA_NO_CLOUD=1`, uses project-local model storage and restricts concurrent model execution. No account or payment is required. It leaves an already-running Ollama service alone. The VS Code extension can discover this same localhost service via **Ollama: Refresh Models**.

Pal selects model inference when `.env.local` contains `PAL_AI_MODE=ollama`. The checked-in example retains `local` for machines without a runtime. To revert to rule-based behavior, set `PAL_AI_MODE=local`. Run `npm run test:ai` for opt-in live model checks; ordinary `npm test` skips them and never requires inference.

On another machine, install Ollama with its official installer or obtain the same portable release, disable cloud features, run `ollama pull qwen3:4b`, and set Pal's mode. Downloads require internet and disk space once; inference runs locally afterward. No automatic download, account signup or paid fallback exists in the app.

`OllamaInterpreter` sends a Zod-derived JSON schema in `format`, uses non-streaming output, disables thinking, sets temperature zero, limits generated output and applies a 45-second timeout. Incomplete/truncated/refused or malformed responses, service errors and absent models all fall back explicitly to local rules. No response can write money. Slow hardware may need a smaller future model or a tuned timeout, but will never trigger a cloud request.

## Classification

Ingestion validates all normalized pages, then classifies new records before the atomic repository merge. Existing corrections and exact remembered rules take precedence. Optional AI sees only the normalized descriptor, merchant, direction and transaction type. Internal-transfer/refund semantics remain deterministic. Peer-payment purpose always stays with the user when uncertain.

AI category, merchant and confidence are runtime-validated; invalid directions/merchant names/output leave the record for review. Confidence >=0.90 is automatic, 0.65-0.89 is provisional/editable, and <0.65 or Uncategorized goes to Quick Check. Learned rules are reapplied at commit so current user choices win. Classifications never move money. In local mode existing fixture/rule classifications remain available, and unknown records stay reviewable. Sync does not repeatedly send previously ingested records to AI.
